# 架构与恢复行为

## 进程与职责

Electron main 启动后端，生成一次性随机访问凭据，持有 HTTP / WebSocket 连接，代理有限的应用接口。前端 renderer 开启 context isolation / sandbox，不启用 Node，preload 只暴露受限桥接。主窗口与悬浮窗复用 React；模型密钥不从数据库返回前端。

后端仅监听 `127.0.0.1` 随机端口，检查请求凭据并拒绝浏览器 Origin。WebSocket 使用子协议传递访问凭据，URL 中没有密钥。Electron 每两秒续租；超过八秒没有控制心跳会暂停。控制连接断开也暂停；父进程消失时后端自行关闭。

FastAPI 的数据操作在单事件循环上进行，SQLite 外键开启，WAL 和 FULL 同步持久化。窗口捕获运行在原生线程，复制帧后交给后台。慢模型请求使用异步网络，不阻塞暂停。

## 会话数据

- `sessions`：名称、设置、当前记忆、有效引导、当前分支和恢复标记。
- `configs`：模型接口设置和凭据引用。
- `runs`：每次开始时保存实际模型配置快照。
- `events`：完整观察、请求、响应、决策、动作、引导与错误。
- `checkpoints`：当前记忆、有效引导、截图引用、配置和事件位置快照。
- `screenshots/{session_id}/{observation_id}.png`：游戏客户区图像，先写临时文件再替换。

名称不是身份。不同会话的数据库访问、上下文、截图和检查点均使用独立 session ID。删除通过外键级联及限定目录清理，不接触游戏文件。

## 决策与动作

0.2.0 使用 LangChain `create_agent` 创建游戏 Agent。`GameChatModel` 将 LangChain 的 SystemMessage/HumanMessage/AIMessage 接到原有三种协议，继续支持自定义 URL、完整端点、JSON 模式和超时。模型凭据仅留在适配器的私有对象中。

`GameTurnMiddleware` 的 before_model 节点等待焦点、截图、装配剧情与引导；model 节点执行一次视觉请求；after_model 节点解析 Decision、核对版本与焦点、记录反馈，再执行输入、等待重读或暂停。wrap_model_call 在真正调用前再次检查任务版本，并只调用一次 handler。中间件不会请求额外反思或动作格式修复。LangChain 自身依赖 LangGraph，但项目入口使用 LangChain Agent API。

`GameAgentState` 明确携带 pending、wait_retries、turn、outcome 和当前 observation；桌面每次调用传回待确认输入与计数，消息只保留当前截图与当前响应。长期剧情从 SQLite 取出并按预算装入 context，不累积所有截图。摘要也通过 GameChatModel 的异步 LangChain 接口调用。界面不显示第几轮，轮数只留在本地请求事件中用于排查。

框架节点使用子任务；ContextVar 记录所属顶层托管任务，区分节点内正常暂停和外部紧急取消。暂停按钮仍立即释放输入、使运行版本失效并取消顶层任务。图不启用可重放检查点；游戏输入的恢复继续遵守下文的 SQLite 日志与人工对齐规则。框架跟踪关闭，图片和剧情只发往用户配置的模型服务。

请求携带观察 ID 和递增运行版本。Decision schema 拒绝额外字段、系统快捷键、无效坐标及选项。暂停、引导、切换、删除使旧版本失效；即使供应商没有响应取消，旧结果也过不了版本检查。

每轮直接截图，模型在一次视觉请求中识别 transition/typing/loading/dialogue/choice/menu/unknown，给出 previous_action_result 和下一 action。存在待确认操作时必须提供反馈。运行层保存模型判断，不再用像素差或台词字符串否决反馈，不再本地等待像素稳定，也不因普通动画作废响应。

动作仍受 JSON Schema、截图编号和运行版本约束。执行前重新取窗口几何，验证身份、前台焦点、客户区坐标、遮挡及允许按键。输入分阶段移动、按下、保持、松开，异步等待期间响应暂停与失焦；部分发送失败释放输入并暂停，不自动重试。

模型 wait 时等待2秒后重读，最多额外两次；转场/逐字显示/加载同样自动等待。same 不强迫补点：只有模型提出重复输入才执行，默认最多额外两次，与读取次数分别记录。重试使用当前模型决策和当前选项坐标，retry_of 引用原动作，original_decision_id 引用首次决策；同一选择未确认时不能改投其他分支。未完整和重复读取不重复进入记忆。

动作阶段：proposed → validated → prepared → sent → observed。observed 记录模型对反馈的判断，不能视为游戏引擎确认。格式失败保存原始回复、字段错误和截图，界面可展开查看，不额外请求修复，也不执行输入。

临时失焦进入 waiting_focus，保留运行任务及已发送输入的待确认记录，禁止输入。焦点代数记录观察到的失焦；请求期间或发送前失焦的旧决策在恢复后作废，重新截图判断。普通画面动画不改变焦点代数。窗口几何变化停止旧坐标动作。主动暂停、引导、接管及控制连接故障递增运行版本并取消任务，旧决策不能自动恢复。

## 长剧情

原始事件完整保留。上下文使用近期剧情、累积章节摘要、事实、推测、问题和有效引导。文本预算为保守估算，预留 schema、图片和输出空间，并记录服务实际返回的用量。

摘要分批进行，保留来源事件 ID、事件范围和版本。历史来源列表存在数据库中，不全部发送给模型。无效摘要不覆盖原始记忆；预算不足时暂停并提示提高预算。

摘要属于有损压缩，不能保证永久记住每个细节；可以通过历史回放及引导校正。没有自动为任何模型提供完整游戏知识。

## 关闭与恢复

模型响应和输入的外部效果无法与数据库事务原子提交。准备发送前写日志，并标记需要核对；观察到新的剧情内容后解除标记。重启把中断的 prepared/sent 标记为 unconfirmed，不执行任何自动补偿输入。

恢复检查点生成新的分支，使用快照记忆而不是拼接后来事件。较晚记录继续用于回放。游戏存档独立于 Agent 检查点，需要用户实际载入并确认。

启动不复用旧 HWND，不自动操作。用户重新绑定、核对游戏进度，再明确继续。

## 后续扩展

严格隔离执行、游戏存档专用适配、检查点分叉比较、长历史检索、自动对话区域标定、限时选择均保留在模块边界之外，不增加新建会话必填项。
